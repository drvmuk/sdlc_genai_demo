### FR-DLT-001: Load Customer and Order Data into Delta Tables

* **Title:** Load Customer and Order Data into Delta Tables
* **Description:** The system must read source CSV data from a specified volume, clean and transform the data, and load it into Delta tables.
* **Preconditions:**
	+ Source CSV files are available at the specified locations: `/Volumes/gen_ai_poc_databrickscoe/sdlc_wizard/customerdata` and `/Volumes/gen_ai_poc_databrickscoe/sdlc_wizard/orderdata`.
	+ The schema of the source data is known: `CustId, Name, EmailId, Region` for Customer and `OrderId, ItemName, PricePerUnit, Qty, Date, CustId` for Order.
* **Main Flow / Functional Steps:**
	1. Read source CSV data from the specified volume into DataFrames.
	2. Remove records with nulls in any mandatory columns in both Customer and Order DataFrames.
	3. Remove duplicate records in both DataFrames based on `CustId` for Customer and `OrderId` for Order.
	4. Add a new column `TotalAmount` to the Order DataFrame calculated as `PricePerUnit * Qty`.

### FR-DLT-002: Create and Populate ordersummary Table

* **Title:** Create and Populate ordersummary Table with SCD Type 2 Logic
* **Description:** The system must create the `ordersummary` table if it does not exist, join Customer and Order data, and implement SCD Type 2 logic to track changes in customer attributes.
* **Preconditions:**
	+ Customer and Order data are loaded into Delta tables.
	+ The `ordersummary` table schema is defined: `CustId, Name, EmailId, Region, OrderId, ItemName, PricePerUnit, Qty, Date, IsActive, StartDate, EndDate`.
* **Main Flow / Functional Steps:**
	1. Join Customer and Order data on `CustId` to create an incoming `ordersummary` view.
	2. Check if the `ordersummary` table exists in the specified catalog (`gen_ai_poc_databrickscoe`) and schema (`sdlc_wizard`); create it if it does not exist.
	3. Implement SCD Type 2 logic:
		- Detect changes in customer attributes (`Name, EmailId, Region`).
		- For changed records, set existing active records to inactive (`IsActive = False`) and update `EndDate` to the current timestamp.
		- Insert new active records with updated customer info, `IsActive = True`, `StartDate` = current timestamp, and `EndDate = NULL`.
		- Retain existing active records unchanged if there are no changes.

### FR-DLT-003: Create and Populate customeraggregatespend Table

* **Title:** Aggregate Spend Data by Customer and Date
* **Description:** The system must aggregate data from the `ordersummary` table to create the `customeraggregatespend` table.
* **Preconditions:**
	+ The `ordersummary` table is populated with data and SCD Type 2 logic is implemented.
	+ The `customeraggregatespend` table schema is defined: `Name, TotalAmount, Date`.
* **Main Flow / Functional Steps:**
	1. Check if the `customeraggregatespend` table exists in the specified catalog (`gen_ai_poc_databrickscoe`) and schema (`sdlc_wizard`); create it if it does not exist.
	2. Aggregate data from active records in `ordersummary`:
		- Group by `Name` and `Date`.
		- Sum `TotalAmount`.
	3. Load the aggregated results into the `customeraggregatespend` table.

### FR-DLT-004: Implement Data Processing Using Delta Live Tables (DLT)

* **Title:** Implement Data Processing Pipeline Using Delta Live Tables
* **Description:** The system must implement the data processing pipeline using Delta Live Tables (DLT) to manage data quality and pipeline dependencies.
* **Preconditions:**
	+ All preceding steps are implemented and functional.
* **Main Flow / Functional Steps:**
	1. Define DLT pipelines for loading data into Delta tables, creating and populating `ordersummary`, and creating and populating `customeraggregatespend`.
	2. Implement DLT to manage data quality checks and pipeline dependencies.

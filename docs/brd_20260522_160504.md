# Executive Summary
- This document outlines the business requirements for ingesting customer and order CSV data into Delta tables, cleansing and enriching data, executing SCD Type 2 handling for customer changes within an ordersummary table, and creating a daily customer spend aggregation. The implementation is to be done using Delta Live Tables as the data pipeline framework.
- The BRD is augmented with a complete Entity Relationship Diagram (ERD) for reference.

# Business Objectives
- Load source CSVs into Delta tables for customer and order data.
- Cleanse customer and order data by removing "Null"/Null literals and duplicates.
- Enrich orders with TotalAmount (PricePerUnit × Qty).
- Create ordersummary by joining customer and order tables, applying SCD Type 2 for customer changes.
- Maintain historical changes of customer data via SCD Type 2 handling.
- Generate customeraggregatespend table with aggregated spend per customer per date.
- Implement end-to-end pipeline using Delta Live Tables.

# In-Scope
- Source ingestion from specified file system locations.
- Creation and management of Delta tables: customer, order, ordersummary, customeraggregatespend.
- Removal of "Null"/Null literals and duplicates.
- Computation of TotalAmount in the order table.
- Join logic and SCD Type 2 handling for customer dimension in ordersummary.
- Aggregation from ordersummary to customeraggregatespend.
- Use of Delta Live Tables for implementation.

# Business Requirements

### BR-APP-001 — Source Ingestion
- Description: Load source CSVs into Delta tables located at specified file system paths for customer and order data.
- Business Value: Enables automated data ingestion from external sources for analytics and reporting.
- Priority: High

### BR-APP-002 — Schema Definition
- Description: Define the customer table with columns CustId, Name, EmailId, Region, and order table with columns OrderId, ItemName, PricePerUnit, Qty, Date, CustId.
- Business Value: Ensures data consistency and supports downstream data processing.
- Priority: High

### BR-APP-003 — Computed TotalAmount Column
- Description: Compute TotalAmount in the order table as PricePerUnit × Qty.
- Business Value: Supports spend analytics and customer value calculation.
- Priority: High

### BR-APP-004 — Data Cleansing
- Description: Remove all "Null"/Null literal values and duplicate records from customer and order tables.
- Business Value: Maintains data quality and reliability for decision-making.
- Priority: High

### BR-APP-005 — Ordersummary Table Creation
- Description: Create the ordersummary Delta table, populated by joining customer and order on CustId.
- Business Value: Centralizes enriched order data for downstream consumption.
- Priority: High

### BR-APP-006 — SCD Type 2 Handling
- Description: On ordersummary, implement SCD Type 2 change logic for customer dimension, maintaining historical versions and updating status fields.
- Business Value: Ensures auditability and accurate reporting on customer changes over time.
- Priority: High

### BR-APP-007 — Aggregated Customer Spend
- Description: Create customeraggregatespend table aggregating TotalAmount by Name and Date, sourced from ordersummary.
- Business Value: Enables analysis on customer spend trends and patterns.
- Priority: High

### BR-APP-008 — Delta Live Tables Implementation
- Description: Use Delta Live Tables to orchestrate the full ETL pipeline as per specified requirements, ensuring dependencies and ordering.
- Business Value: Enables scalable, maintainable, and automated ETL processing.
- Priority: High

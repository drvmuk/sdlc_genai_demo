## 1. Overview
- Purpose:
- Define functional requirements for building a Delta Live Tables (DLT) pipeline to ingest customer and order CSV data, cleanse and transform it, compute totals, manage an SCD Type 2 ordersummary table, and produce a daily customer aggregate spend table within the gen_ai_poc_databrickscoe catalog and sdlc_wizard schema.

## 2. Functional Requirements
- FR-DLT-001: Ingest Customer CSV to Delta
- Description: Read customer CSV files from the specified volume path and load them into a managed Delta table.
- Preconditions:
  - Source files available at /Volumes/gen_ai_poc_databrickscoe/sdlc_wizard/customerdata
  - Catalog gen_ai_poc_databrickscoe and schema sdlc_wizard exist or can be created
  - DLT pipeline has service principal/cluster permissions to read volume and write catalog
- Main Flow:
  1. Configure a DLT dataset to read CSVs with header inference for columns CustId, Name, EmailId, Region
  2. Write data to a bronze/silver Delta table named customer in gen_ai_poc_databrickscoe.sdlc_wizard
- Alternate/Exception Flows:
  - If schema inference fails, apply a defined schema with expected data types and continue
  - If source path is empty, produce an empty but valid table version and alert
- Acceptance Criteria:
  - Data from the volume is available as a Delta table gen_ai_poc_databrickscoe.sdlc_wizard.customer with defined schema
  - Read and write operations are logged in DLT event logs

- FR-DLT-002: Ingest Order CSV to Delta
- Description: Read order CSV files from the specified volume path and load them into a managed Delta table.
- Preconditions:
  - Source files available at /Volumes/gen_ai_poc_databrickscoe/sdlc_wizard/orderdata
  - DLT pipeline permissions configured
- Main Flow:
  1. Configure a DLT dataset to read CSVs with header inference for columns OrderId, ItemName, PricePerUnit, Qty, Date, CustId
  2. Write data to a bronze/silver Delta table named order in gen_ai_poc_databrickscoe.sdlc_wizard
- Alternate/Exception Flows:
  - If malformed records are detected, quarantine to an error dataset and continue
  - If source path is empty, create an empty table version and alert
- Acceptance Criteria:
  - Data is available as Delta table gen_ai_poc_databrickscoe.sdlc_wizard.order with defined schema
  - Malformed records handling is traceable

- FR-DLT-003: Compute TotalAmount in Orders
- Description: Add a computed column TotalAmount = PricePerUnit * Qty to the order table within the DLT pipeline.
- Preconditions:
  - FR-DLT-002 completed successfully
- Main Flow:
  1. Define a transformation dataset that casts PricePerUnit and Qty to numeric types
  2. Compute TotalAmount and persist to the refined orders dataset
- Alternate/Exception Flows:
  - If non-numeric values are found, coerce to null and route rows to a data quality expectation for review
- Acceptance Criteria:
  - Orders dataset includes a non-nullable TotalAmount where inputs are valid
  - Data quality expectations report invalid rows count

- FR-DLT-004: Data Cleansing for Nulls and Duplicates
- Description: Remove records with Null/"Null" textual values in key fields and deduplicate records in both customer and order datasets.
- Preconditions:
  - FR-DLT-001 and FR-DLT-002 completed
- Main Flow:
  1. Normalize "Null"/"NULL"/null textual representations to actual nulls
  2. Filter out records where required fields are null (customer: CustId, Name, EmailId; order: OrderId, CustId, Date)
  3. Deduplicate by business keys (customer: CustId; order: OrderId) using latest record by ingestion time
- Alternate/Exception Flows:
  - If duplicates have conflicting data, retain the latest by event or ingestion timestamp and log conflicts
- Acceptance Criteria:
  - No records with null required keys remain
  - No duplicate keys remain in target refined datasets

- FR-DLT-005: Create Ordersummary Table If Not Exists
- Description: Ensure existence of a Delta table ordersummary in the specified catalog and schema.
- Preconditions:
  - Catalog gen_ai_poc_databrickscoe and schema sdlc_wizard accessible
- Main Flow:
  1. Define a DLT target dataset ordersummary with schema CustId, Name, EmailId, Region, OrderId, ItemName, PricePerUnit, Qty, Date, plus SCD2 metadata columns <TBD>
  2. Configure table properties and expectations as per standards
- Alternate/Exception Flows:
  - If table exists with differing schema, apply schema evolution where compatible and log
- Acceptance Criteria:
  - ordersummary table exists in gen_ai_poc_databrickscoe.sdlc_wizard with required columns and metadata

- FR-DLT-006: Join Customer and Order Data
- Description: Join cleansed customer and order datasets on CustId to produce enriched order records.
- Preconditions:
  - FR-DLT-003 and FR-DLT-004 completed
- Main Flow:
  1. Perform inner join of customer and order on CustId
  2. Select columns required for ordersummary, including TotalAmount
- Alternate/Exception Flows:
  - If a CustId in orders has no customer match, log to a mismatch dataset and exclude from join
- Acceptance Criteria:
  - Enriched dataset includes all expected columns and is join-consistent

- FR-DLT-007: Implement SCD Type 2 for Ordersummary
- Description: Manage ordersummary as an SCD Type 2 table, tracking history and changes from the customer dimension.
- Preconditions:
  - FR-DLT-005 and FR-DLT-006 available
- Main Flow:
  1. Define SCD2 metadata columns: IsActive (boolean), StartDate (date/timestamp), EndDate (date/timestamp), RecordHash <TBD>, SurrogateKey <TBD>
  2. Compare incoming joined records with current active ordersummary records by business keys (CustId, OrderId)
  3. If non-key attribute changes detected for customer attributes (e.g., Name, EmailId, Region), expire existing active records (IsActive=false, set EndDate to current date)
  4. Insert new active records with updated attributes (IsActive=true, StartDate=current date, EndDate=null)
  5. For unchanged records, do nothing
- Alternate/Exception Flows:
  - If multiple active records exist for the same business key, resolve by latest StartDate and flag data issue
- Acceptance Criteria:
  - Only one active record per CustId+OrderId at a time
  - Historical versions preserved with correct StartDate/EndDate
  - Changes in customer attributes propagate to ordersummary with old rows inactivated and new rows activated

- FR-DLT-008: Compute and Store TotalAmount in Ordersummary
- Description: Ensure TotalAmount from orders is carried into ordersummary and available for downstream aggregation.
- Preconditions:
  - FR-DLT-003 and FR-DLT-006 completed
- Main Flow:
  1. Include TotalAmount in the SCD2 insert/update logic
  2. Validate non-negative TotalAmount values
- Alternate/Exception Flows:
  - If TotalAmount is null or negative, quarantine the record and exclude from SCD2 upsert
- Acceptance Criteria:
  - ordersummary contains accurate TotalAmount for active records

- FR-DLT-010: Aggregate TotalAmount by Name and Date

- Preconditions:
  - FR-DLT-007 and FR-DLT-009 completed
- Main Flow:
  1. Filter ordersummary to active records only
  2. Group by Name and Date; sum TotalAmount as TotalAmount

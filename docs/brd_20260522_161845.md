# Document Control
- System Name: Application

# Executive Summary
- This document defines the business requirements for the Application system, focusing on ingesting customer and order CSV data into Delta tables, performing data cleansing, calculating order totals, handling Slowly Changing Dimension (SCD) Type 2 for customer updates, and generating daily spend aggregates, all orchestrated via Delta Live Tables.

# Business Objectives
- Load customer and order data from source CSV files into managed Delta tables.
- Cleanse ingested data by removing null literals and duplicates.
- Enrich order data with a computed TotalAmount as PricePerUnit × Qty.
- Join customer and order datasets to create an ordersummary Delta table.
- Apply SCD Type 2 methodology to maintain historical accuracy of customer data.
- Aggregate customer spend daily into the customeraggregatespend table.
- Coordinate all steps using Delta Live Tables as the implementation engine.

# In-Scope
- Ingestion from defined customer and order source paths into Delta tables.
- Schema mapping and creation of Delta tables: customer, order, ordersummary, customeraggregatespend.
- Data cleansing (null and duplicate removal).
- Calculation and population of derived columns.
- SCD Type 2 historical tracking for customers in ordersummary.
- Aggregation of order data for daily spend tracking.
- Process flow driven by Delta Live Tables.

# Business Requirements

### BR-BI-001 — Source Data Ingestion
- Description: Load customer and order CSV files from specified file paths into respective Delta tables.
- Business Value: Ensures accurate, repeatable ingestion of raw data for downstream processing.
- Priority: High

### BR-BI-002 — Schema Enforcement
- Description: Maintain the predefined schema for both customer and order Delta tables.
- Business Value: Drives data quality and structural consistency.
- Priority: High

### BR-BI-003 — Computed Field Enhancement
- Description: Compute TotalAmount in the order table using PricePerUnit × Qty.
- Business Value: Enables meaningful financial aggregations.
- Priority: High

### BR-BI-004 — Data Cleansing
- Description: Remove "Null"/Null literals and duplicate records from both customer and order tables.
- Business Value: Improves data integrity and reliability of subsequent analysis.
- Priority: High

### BR-BI-005 — Join Operations and Table Creation
- Description: Join customer and order on CustId to create the ordersummary table with SCD Type 2 handling.
- Business Value: Correlates transactional and reference data with historical accuracy.
- Priority: High

### BR-BI-006 — SCD Type 2 Historical Accuracy
- Description: Apply SCD Type 2 logic in ordersummary, setting prior records as Inactive and updating StartDate/EndDate as customers change.
- Business Value: Maintains a historical trail of customer data for audit and business intelligence.
- Priority: High

### BR-BI-007 — Aggregate Spend Tracking
- Description: Aggregate ordersummary data by Name and Date to create the customeraggregatespend table.
- Business Value: Supports daily customer-level financial insights.
- Priority: High

### BR-BI-008 — Orchestrated Execution
- Description: Implement all processing steps using Delta Live Tables in specified sequence.
- Business Value: Ensures maintainable, scalable, and operationalized data pipelines.
- Priority: High

# 1. Conceptual Data Model

- Entities:
  - Customer
  - Order
  - OrderSummary
  - CustomerAggregateSpend

- Relationships:
  - Customer places Order (1-to-many: Customer → Order)
  - OrderSummary is derived by joining Customer and Order, tracking SCD Type 2 history
  - CustomerAggregateSpend aggregates OrderSummary by customer and date

- Entity Definitions:
  - Customer: Contains customer master data.
  - Order: Represents purchases made by customers.
  - OrderSummary: Combines customer and order data, tracks historical changes.
  - CustomerAggregateSpend: Aggregates each customer’s total daily spending.

# 2. Logical Data Model

- Customer
  - CustId (Primary Key)
  - Name
  - EmailId
  - Region

- Order
  - OrderId (Primary Key)
  - ItemName
  - PricePerUnit
  - Qty
  - Date
  - CustId (Foreign Key → Customer.CustId)
  - TotalAmount (Computed: PricePerUnit × Qty)

- OrderSummary
  - CustId
  - Name
  - EmailId
  - Region
  - OrderId
  - ItemName
  - PricePerUnit
  - Qty
  - Date
  - StartDate (SCD2 Field, <TBD>)
  - EndDate   (SCD2 Field, <TBD>)
  - Active    (SCD2 Field, <TBD>)
  - Composite Key: CustId, OrderId, StartDate
  - FKs: CustId (to Customer), OrderId (to Order)

- CustomerAggregateSpend
  - Name
  - TotalAmount (SUM aggregated per name/date)
  - Date
  - Composite Key: Name, Date

- Normalization:
  - All tables are in 3NF.
  - Each non-key attribute depends on the full primary key.

- Business Rules by Entity:
  - Remove "Null"/Null literals and duplicates (Customer, Order)
  - Compute TotalAmount in Order.
  - Use SCD Type 2 tracking in OrderSummary.
  - Aggregate spend by Name and Date in CustomerAggregateSpend.

# Executive Summary
- The Application ingests customer and order CSV data into Delta tables, performs data cleansing and computation of TotalAmount, joins data for an ordersummary table with SCD Type 2 handling, and creates a customeraggregatespend table aggregating daily spend.
- Implementation is executed using Delta Live Tables.
- All processing logic, schemas, and rules are preserved as per documented requirements.

# Business Objectives
- Ingest customer and order CSV files into Delta tables for further processing.
- Cleanse data by removing "Null" or Null values and duplicate records.
- Calculate TotalAmount as a derived field in the order table.
- Join customer and order data to generate an ordersummary table, handling customer changes with SCD Type 2.
- Aggregate spend per Name and Date in a customeraggregatespend table.
- Implement the data pipeline end-to-end using Delta Live Tables.

# In-Scope

# Business Requirements

### BR-APP-001 — Source Data Ingestion
- Description: Load customer and order CSV files from defined filesystem paths into Delta format tables.
- Business Value: Enables a structured, governed raw data layer.
- Priority: High

### BR-APP-002 — Table Schemas Standardization
- Description: Enforce specific schemas for customer (CustId, Name, EmailId, Region) and order (OrderId, ItemName, PricePerUnit, Qty, Date, CustId) tables.
- Business Value: Ensures consistent structure for all downstream operations.
- Priority: High

### BR-APP-003 — Computed Field: TotalAmount
- Description: Add TotalAmount field to order table calculated as PricePerUnit × Qty.
- Business Value: Supports accurate spend measurements and reporting.
- Priority: High

### BR-APP-004 — Data Cleansing
- Description: Remove "Null" and Null literals and deduplicate records in both customer and order tables.
- Business Value: Increases data reliability and trustworthiness for analytics.
- Priority: High

### BR-APP-005 — Ordersummary Table Creation
- Description: Join customer and order tables on CustId to form an ordersummary table, applying SCD Type 2 change tracking.
- Business Value: Maintains complete audit trail of customer data changes in transactions.
- Priority: High

### BR-APP-006 — SCD Type 2 Handling Logic
- Description: Process changes in customer attributes using SCD Type 2 approach, updating previous records to Inactive and new records to Active, with StartDate and EndDate tracking.
- Business Value: Retains historical versions, critical for compliance and audit.
- Priority: High

### BR-APP-007 — Aggregate Spend Calculation
- Description: Aggregate ordersummary data to calculate daily spend per customer in the customeraggregatespend table using sum(TotalAmount), grouped by Name and Date.
- Business Value: Enables business trend analysis and spend monitoring.
- Priority: Medium

### BR-APP-008 — Pipeline Implementation with Delta Live Tables
- Description: All processing steps (1–7) are implemented using Delta Live Tables pipeline.
- Business Value: Ensures automation, reliability, and scalability for production use.
- Priority: High
